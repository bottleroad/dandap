# dandap-commit

커밋 메시지를 Conventional Commits 형식으로 작성한다. 접두어는 영어, 제목과 본문은 한국어 평서체(`-다`)로 쓴다. 무엇을 바꿨는지보다 왜 바꿨는지를 우선한다.

## 제목 줄

* 형식: `<type>(<scope>): <제목>`. `<scope>`는 생략할 수 있다.
* type: `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `chore`, `build`, `ci`, `style`, `revert`
* scope: 영어 소문자 식별자(`auth`, `hooks`, `readme`)를 쓴다.
* 제목: 한국어 평서체 현재형으로 쓴다. 예: `토큰 만료 조건을 수정한다`
  * 단답체(`수정함`), 과거형(`수정했다`), 해요체(`수정해요`)는 쓰지 않는다.
* 길이: 가능하면 50자 이내, 최대 72자.
* 제목 끝에는 마침표를 붙이지 않는다.

## 본문 (필요할 때만)

* 제목만으로 의도가 분명하면 본문을 생략한다.
* 본문이 필요한 경우: 이유가 자명하지 않을 때, 호환성이 깨질 때, 마이그레이션 안내가 필요할 때, 이슈를 연결할 때.
* 제목과 본문 사이는 빈 줄 하나로 띄운다.
* 한 줄은 72자 안에서 줄바꿈한다.
* 문장은 평서체로 쓰고 마침표로 끝낸다.
* 목록은 `-`를 쓴다.
* 이슈 참조는 맨 끝에 둔다: `Closes #42`, `Refs #17`.

## 넣지 않는 것

* "이 커밋은 ~한다", "제가", "이번에" 같은 서술. 변경 내용은 diff가 말한다.
* 이모지(프로젝트 규칙이 요구하는 경우는 예외).
* scope가 이미 말하는 파일명의 반복.
* AI 생성 문구. 단, 사용자나 하네스 지침이 요구하는 trailer(`Co-Authored-By` 등)는 지침대로 맨 끝에 추가한다.

## 반드시 본문을 쓰는 경우

호환성이 깨지는 변경, 보안 수정, 데이터 마이그레이션, 이전 커밋 되돌리기(revert)는 제목만으로 줄이지 않는다.

## 예시

* Bad: `fix: 토큰 만료 버그 수정함`
* Good:
  ```
  fix(auth): 토큰 만료 조건을 수정한다

  만료 시각과 같은 경우에도 유효로 처리되던 문제를 고친다.
  `<`를 `<=`로 바꾼다.
  ```

* 호환성이 깨지는 변경:
  ```
  feat(api)!: /v1/orders 경로를 /v1/checkout으로 바꾼다

  BREAKING CHANGE: /v1/orders를 쓰는 클라이언트는 2026-12-31까지
  /v1/checkout으로 옮겨야 한다. 이후 기존 경로는 410을 반환한다.
  ```

## 범위

커밋 메시지만 작성한다. `git add`, `git commit`, `git commit --amend`는 사용자가 따로 요청할 때만 실행한다. 결과는 바로 붙여 넣을 수 있도록 코드 블록으로 출력한다.
